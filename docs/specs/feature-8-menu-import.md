# Feature #8: Импорт меню из CSV/XLSX (файловый коннектор)

## Обзор
Файловый импорт — вид коннектора, встроенный в ядро (ТЗ 4.2): меню заведения загружается из файла CSV или XLSX, а не из кассы по Integration API. Он нужен в двух случаях: на прототипе (этап 1), пока нет Integration API (#16) и коннектора Yii2 (#18), и у заведений, касса которых не умеет выгружать меню (ТЗ 1: «без коннектора система тоже работает: меню загружается из файла»).

Ценность: на этапе 1 гостевое меню (#10), поиск и ИИ-диалог (#11, #12) работают на настоящем меню кассы «restoran», а не только на вымышленном сиде (#53). Цены и позиции по-прежнему приходят из одного источника (файл = выгрузка кассы), в админке они не редактируются (FR-16).

Ядро фичи — общий сервис применения **снимка меню** `MenuSnapshot` (тот же состав, что у тела `PUT /menu`, ТЗ 4.4), пакет `app/menu_sync` (arch ADR-8.1). Файл разбирается в снимок, снимок проверяется и применяется к таблицам меню #7 по `external_id`: новые позиции создаются, изменённые обновляются, пропавшие скрываются (`is_hidden`), вернувшиеся показываются снова. Каждый запуск записывается в журнал `menu_sync_runs`; снимок с тем же хешем не пересчитывается (INT-1). #16 вызывает тот же `apply_menu_snapshot` из `PUT /menu`, новой логики применения в #16 нет.

Запуск на этапе 1 — CLI `python -m app.menu_sync` для оператора сервера. Загрузка файла из админки появится после авторизации персонала (#19) в задачах админки (#29, FR-20); контракт эндпоинта зафиксирован в arch ADR-8.6.

Архитектурные решения — `docs/arch/feature-8-menu-import.md` (ADR-8.1…ADR-8.8); при расхождении приоритет у arch doc. Схема меню — `docs/arch/feature-7-data-model.md` (ревизия `0002_menu`).

## Роли
- **Оператор** (разработчик, владелец платформы с доступом к серверу и `.env`) — запускает `python -m app.menu_sync check|import`; на этапе 1 это единственный способ загрузить меню из файла.
- **Администратор заведения** — готовит файл (выгрузка из кассы или таблица) и передаёт оператору; загрузку из админки получит после #19.
- **Коннектор кассы** (технический) — в #16 отправляет тот же снимок через `PUT /menu`; в #8 не участвует, но использует общий сервис.
- **Гость, ИИ** — видят результат: только не скрытые позиции с актуальными ценами (#10, #11).

## Формат файла (CSV и XLSX — одинаковые колонки, arch ADR-8.2)
Одна строка — одна позиция; данные категории повторяются в каждой строке её позиций. Заголовок — первая непустая строка; имена колонок без учёта регистра и пробелов по краям; порядок любой. Колонка, имя которой начинается с `#`, игнорируется; любая другая неизвестная колонка — ошибка `unknown_column` (опечатка в `is_available` или `price_vip` не должна молча пропасть); повтор колонки — `duplicate_column`.

| Колонка | Обязательна | Значение | Поле снимка (ТЗ 4.4) / таблица #7 |
|---|---|---|---|
| `category_external_id` | да | ID категории в кассе, 1–64 символа | `category_external_id` / `categories.external_id` |
| `category_name` | да | название категории, 1–200 символов | `categories.pos_name` |
| `category_sort_key` | нет | порядок категории, ≤ 64 | `categories.sort_key` |
| `external_id` | да | ID позиции, 1–64 символа, уникален в файле; `007` и `7` — разные | `menu_items.external_id` |
| `name` | да | название позиции, 1–200 символов | `menu_items.pos_name` |
| `price_default` | да | цена тарифа `default` | `menu_item_prices (price_tier='default')` |
| `price_<tier>` | нет | цена тарифа `<tier>` по `PRICE_TIER_PATTERN`; пустая ячейка — у позиции этого тарифа нет | `menu_item_prices` |
| `currency` | нет | ISO 4217; пусто — валюта заведения; иная валюта — отклоняется весь снимок | `menu_items.currency` |
| `station` | нет | станция (кухня, бар), ≤ 100 | `menu_items.station` |
| `sort_key` | нет | порядок позиции, ≤ 64 | `menu_items.sort_key` |
| `is_available` | нет | `1/0`, `true/false`, `yes/no`. Нет колонки — наличие не меняется; колонка есть — значение обязательно в каждой строке | `menu_items.is_available` |

- Деньги: `8`, `8.5`, `8.50`; без минуса, экспоненты и разделителей тысяч; максимум `99999999.99`; больше двух знаков — ошибка `too_many_decimals` (ядро не округляет, округляет выгрузка, ТЗ C-07). Нулевая цена — предупреждение `zero_price`, применению не мешает.
- Десятичная запятая (`8,50`) допускается **только** в CSV с разделителем `;` (так сохраняет Excel с русской и азербайджанской локалью); в CSV с `,` запятая — разделитель полей.
- Текст: пробелы по краям обрезаются, пустая строка — «нет значения», управляющие символы — ошибка.
- CSV: UTF-8, BOM допускается; другая кодировка — ошибка `encoding` с подсказкой «Сохраните как “CSV UTF-8”»; разделитель `,` или `;` определяется по заголовку; кавычки RFC 4180; пустые строки пропускаются.
- XLSX: лист из `--sheet`; если не задан — лист `menu` (без учёта регистра), иначе первый лист. Берутся сохранённые значения, формулы не вычисляются; `.xls`, `.xlsm` — `unsupported_format`; даты и ошибки Excel в ячейках — `invalid_cell_type`.
- Лимиты (константы в коде): файл 5 МБ, 5 000 строк данных, 50 колонок, 1 000 символов в ячейке; распакованный XLSX ≤ 50 МБ, сжатие члена ≤ 100×.
- Синтетический пример — `backend/tests/fixtures/menu/menu_valid.csv` (вымышленные блюда); реальные выгрузки — только в `local-data/` (в `.gitignore`) или вне репозитория.

Пример CSV с разделителем `;` (вымышленные данные):
```csv
category_external_id;category_name;category_sort_key;external_id;name;sort_key;station;price_default;price_vip;is_available
10;Demo Soups;01;1001;Demo Lentil Soup;01001;Kitchen;4,50;5,50;1
10;Demo Soups;01;1002;Demo Tomato Soup;01002;Kitchen;4,00;;1
20;Demo Drinks;02;2001;Demo Lemonade;02001;Bar;3,00;3,50;no
```

## Functional Requirements
- FR-1: тип денег `MoneyStr` (`app/schemas/money.py`: `Decimal` без `float`, не больше двух знаков, ≥ 0, ≤ `99999999.99`) и модель снимка `MenuSnapshot {categories[], items[]}` (`app/menu_sync/snapshot.py`, Pydantic `extra="forbid"`) в форме тела `PUT /menu` (ТЗ 4.4). Проверка снимка собирает **все** проблемы с кодом `IssueCode`, элементом и сообщением на русском: повтор `external_id`, ссылка на отсутствующую категорию, нет цены `default`, недопустимое имя тарифа, длины и шаблоны `0002_menu`, валюта позиции ≠ `tenants.currency` (`currency_mismatch`, `resolve_currency`), пустой снимок (`empty_snapshot`). Story #61. Хеш снимка `snapshot_hash` (SHA-256 канонического JSON, порядок категорий и позиций не влияет) — в story #63 (FR-4). (ТЗ 4.4, INT-1, INT-2; arch ADR-8.1, ADR-8.3, ADR-8.5)
- FR-2: план и применение снимка (`plan_menu_sync` — чистая функция без БД, `apply_menu_snapshot` — запись): сопоставление по `(tenant_id, external_id)`; создание, обновление, скрытие пропавших (`is_hidden = true`, строки не удаляются), возврат скрытых, снова попавших в снимок; тарифы из снимка добавляются или обновляются, тарифы позиции, которых нет в снимке, удаляются; `is_available = None` — наличие не меняется, у новой позиции `true`; `menu_item_meta` и `menu_item_allergens` не трогаются. Данные других заведений не затрагиваются. Story #62. (ТЗ INT-2, FR-16, FR-17, 4.4; arch ADR-8.3)
- FR-3: «всё или ничего»: при любой ошибке (`severity=error`) в таблицы меню ничего не пишется, в отчёте — полный список проблем (до 100 и «ещё N»). Защита от массового скрытия: если план скрывает не меньше 10 позиций и не меньше 30 % видимых сейчас — ошибка `mass_hide`, снимается флагом `--allow-mass-hide`; пустой снимок отвергается всегда. Применение идёт под транзакционным advisory lock заведения; lock занят — `MenuSyncBusyError` без ожидания. `--dry-run` строит тот же план под тем же lock и ничего не пишет. Story #62. (ТЗ INT-2; arch ADR-8.4)
- FR-4: журнал `menu_sync_runs` (ревизия `0005_menu_sync_runs`): заведение, `source` (`file`/`connector`), `source_ref` (имя файла без каталога), `status` (`applied`/`unchanged`/`rejected`, `MenuSyncStatus`), хеш снимка, `started_at`/`finished_at`, счётчики и проблемы. Если хеш совпал с хешем последней записи заведения со статусом `applied`/`unchanged` (любого источника) и нет `--force`, меню не пересчитывается, пишется запись `unchanged`. Отклонённый снимок журналируется отдельной транзакцией после отката (`record_rejected_run`). `connectors.last_menu_hash` в #16 не создаётся: источник правды о хеше и времени синхронизации — журнал. Данные журнала — для FR-20 (#29) и алерта INT-4 (#23). Story #63. (ТЗ INT-1, FR-20, INT-4, NFR-6; arch ADR-8.5)
- FR-5: разбор CSV в снимок по формату выше (`app/menu_sync/files/format.py`, `csv_reader.py`); каждая проблема указывает номер физической строки файла, колонку и причину на русском; описание формата для администратора — в README («Импорт меню»); синтетический пример — `backend/tests/fixtures/menu/menu_valid.csv`. Story #64. (ТЗ 4.2, INT-2; arch ADR-8.2)
- FR-6: разбор XLSX в тот же снимок (`app/menu_sync/files/xlsx_reader.py`, `openpyxl` только в этом модуле, `defusedxml`) с тем же отчётом (лист, строка, колонка) и защитой от zip-бомбы. Story #65. (ТЗ 4.2; arch ADR-8.2, ADR-8.7)
- FR-7: CLI `python -m app.menu_sync check FILE [--sheet NAME] [--json]` (без БД и `.env`) и `python -m app.menu_sync import FILE --tenant UUID [--dry-run] [--force] [--allow-mass-hide] [--sheet NAME] [--database-url URL] [--json]`. Коды выхода: 0 — успех (применено, `unchanged`, `check`/`--dry-run` без ошибок); 1 — ошибка окружения (нет или нечитаем файл, конфигурация, БД, нет заведения); 2 — ошибки в данных, ничего не записано; 3 — синхронизация меню этого заведения уже идёт. Разрешено при `APP_ENV=prod`; работает в `single` и `scaled`. Story #66. (ТЗ 4.2, 9.2; arch ADR-8.6)
- FR-8: выгрузка меню кассы «restoran» в файл формата #8 консольной командой Yii2 `php yii ai-export-menu <file.csv>` в репозитории кассы (`commands/AiExportMenuController.php`, `MenuSnapshotBuilder` с соответствием ТЗ A.2, переиспользуется в #18): `type` → категория, `menu` → позиция, `store.name` → станция, `menu.price` → `price_default` (округление до двух знаков), `menu.price_vip > 0` → `price_vip`, иначе пусто; `menu.disabled` = 0 или `NULL` → `is_available = 1`; `currency` пусто. Реальная выгрузка — в `local-data/` ai-waiter или вне репозитория; проверка — `python -m app.menu_sync check`. Story #67. (ТЗ A.2, C-07; arch ADR-8.8)

## Non-Functional Requirements
- NFR-1 Мультиарендность (ТЗ NFR-4): `tenant_id` — аргумент CLI (позже — из учётной записи админа), никогда не из файла; все запросы сервиса фильтруются по нему; составные FK `(tenant_id, x_id)` (DEC-006) исключают ссылку на чужую категорию; импорт в заведение A не меняет меню заведения B с теми же `external_id` (db-тест).
- NFR-2 Целостность данных кассы (ТЗ INT-2, spec #7 NFR-7): строки `categories`, `menu_items` не удаляются; удаляются только строки `menu_item_prices` тарифов, которых больше нет у позиции.
- NFR-3 Атомарность и параллельность (arch ADR-8.4): один снимок — одна транзакция; advisory lock заведения (`MENU_SYNC_LOCK_NAMESPACE = 8`) исключает два одновременных применения (CLI и служба, две команды), второй запуск сразу получает отказ; тот же lock обязаны брать `PUT /stoplist` (#16) и ручной стоп-лист (#28).
- NFR-4 Деньги (CLAUDE.md, ADR-7.4): `Decimal`/`MoneyStr` от разбора файла до `NUMERIC(10,2)`, без `float`; числа XLSX переводятся через `repr`, шум двоичной дроби (< 1e-9) округляется, остальное с > 2 знаками — ошибка.
- NFR-5 Производительность: файл на 2 000 позиций разбирается, проверяется и применяется не дольше 10 с на сервере пилота (Windows Server 2019, `single`); запись пакетами, а не по строке; неизменённый снимок не трогает таблицы меню.
- NFR-6 Безопасность (ТЗ NFR-4, AI-3; arch ADR-8.7): защита от XML-бомб и XXE (`defusedxml`), от zip-бомбы (проверка архива до openpyxl), формулы не вычисляются, макросы отвергаются; названия и станции — данные, не инструкции (длина ограничена, управляющие символы отвергнуты); в журнал и логи не попадают путь к файлу (только имя), содержимое файла и пароль БД; значения ячеек в отчёте обрезаются до 60 символов.
- NFR-7 Переносимость (ТЗ NFR-8, 9.2, DEC-004): одинаково на Windows и Linux — `pathlib`, явная `utf-8`; `openpyxl` и `defusedxml` — чистый Python, ставятся `uv sync` без компилятора; лимиты — константы в коде, не переменные окружения.
- NFR-8 Наблюдаемость (ТЗ NFR-6): итог запуска — строка `menu_sync_runs` и структурированная запись в лог (заведение, источник, статус, счётчики, длительность, хеш).
- NFR-9 Публичный репозиторий (CLAUDE.md): в репозиторий попадает только синтетический пример; реальная выгрузка — `local-data/` (в `.gitignore`) или вне репозитория; код под кассу «restoran» в ai-waiter не попадает.
- NFR-10 Качество и границы импортов: `ruff` и `pytest` без ошибок, покрытие нового кода ≥ 95%; снимок, план, разбор файлов и `check` — unit-тесты без БД (Windows и Linux); применение, журнал и `import` — db-тесты (DEC-008). Границы (arch ADR-8.1): `openpyxl` только в `xlsx_reader.py`; `app/menu_sync/files/**` не импортирует SQLAlchemy, `app.db` и `app.models` (кроме `app.models.enums`); `app/menu_sync/**` не импортирует FastAPI; `app/core/**` не импортирует `app.menu_sync`.

> Нумерация FR/NFR в spec — локальная для фичи; рядом указан исходный пункт ТЗ.

## Acceptance Criteria (Given / When / Then)
### AC-1 (story #61 — модель снимка)
**Given** заведение с валютой AZN и снимок из трёх позиций, в котором у одной позиции нет цены `default`, у второй валюта USD, а третья ссылается на категорию, которой нет в снимке
**When** снимок проверяется
**Then** результат содержит три ошибки (среди них `currency_mismatch`), каждая с `external_id` позиции, полем и причиной на русском, а корректный снимок того же размера проходит проверку без ошибок и его хеш не зависит от порядка позиций

### AC-2 (story #62 — применение снимка)
**Given** в меню заведения позиции `1001`, `1002`, `1003` (у `1003` есть `menu_item_meta`), позиция `1004` скрыта, а у другого заведения есть позиция `1001`
**When** применяется корректный снимок с позициями `1001` (новая цена), `1002`, `1004` и новой `1005`
**Then** у `1001` новая цена, `1003` получает `is_hidden = true` и сохраняет `menu_item_meta`, у `1004` снова `is_hidden = false`, `1005` создана, ни одна строка `categories`/`menu_items` не удалена, а позиция `1001` другого заведения не изменилась

### AC-3 (story #63 — журнал и хеш)
**Given** снимок меню заведения применён, в `menu_sync_runs` есть запись `applied` с его хешем
**When** тот же снимок (те же данные в другом порядке строк) применяется снова без `--force`
**Then** таблицы меню не меняются (`updated_at`, `synced_at` прежние), в `menu_sync_runs` появляется запись `unchanged` с тем же хешем и временем запуска

### AC-4 (story #64 — CSV)
**Given** CSV-файл в UTF-8 с BOM, разделителем `;` и ценами с запятой, в котором строка 4 содержит цену `abc`, а строка 7 повторяет `external_id` строки 3
**When** файл разбирается в снимок
**Then** отчёт содержит ошибки «строка 4, колонка `price_default`: …» и «строка 7, колонка `external_id`: повтор (строка 3)», снимок не возвращается, а исправленный файл даёт снимок с ценой `Decimal("4.50")`

### AC-5 (story #65 — XLSX)
**Given** XLSX-файл с данными синтетического CSV-примера на втором листе `Menu` (первый лист — другой), где цены заданы числами в ячейках
**When** файл разбирается без указания листа
**Then** выбирается лист `Menu`, а снимок совпадает со снимком из CSV-примера, включая цены `Decimal` с двумя знаками

### AC-6 (story #66 — CLI)
**Given** база с применёнными миграциями, заведение и синтетический пример `menu_valid.csv`
**When** оператор запускает `import --tenant <uuid>` сначала с `--dry-run`, затем без него, затем ещё раз с тем же файлом
**Then** первый запуск печатает план и не меняет БД (код 0), второй применяет меню со статусом `applied` (код 0), третий печатает статус `unchanged` (код 0); файл с ошибками в данных даёт код 2 без изменений меню, а занятая блокировка — код 3

### AC-7 (story #67 — выгрузка «restoran»)
**Given** база кассы «restoran» с меню, где есть позиция с `price_vip = 0`, позиция с `disabled = 1` и цена во float вида `7.999999`
**When** оператор запускает `php yii ai-export-menu <путь к ai-waiter>/local-data/menu.csv` (файл пишется в `local-data/` репозитория ai-waiter, вне репозитория кассы), а затем `python -m app.menu_sync check` на результате
**Then** `check` завершается кодом 0; у позиции с `price_vip = 0` колонка `price_vip` пустая, позиции с `disabled = 1` в файле нет (колонка `is_available` не выгружается; решение пользователя 2026-10-13 по вопросу 5), цена `8.00`, а файл лежит в `local-data/` (игнорируется git)

## Открытые вопросы
**Решения пользователя 2026-10-13:** вопросы 1–4 и 8 — рекомендации приняты. Вопрос 5 (menu.disabled) — блюдо снято с продажи: позиции с disabled = 1 не выгружаются и скрываются синхронизацией (ТЗ A.2 исправлено). Код выгрузки — команда Yii2 в репозитории кассы (рекомендация принята; для других касс — свои коннекторы по приложению B ТЗ). Источник данных — локальная MariaDB 10.3 OpenServer; таблица `menu` в ней сейчас пустая (0 строк), реальное меню нужно получить свежим дампом от заведения.

Нумерация по важности; рекомендация — в конце каждого пункта. Решения architect — `docs/arch/feature-8-menu-import.md`.

1. **Политика ошибок и чужая валюта** (arch, вопрос 2). Применить корректные строки или ничего? Частичное применение опасно: позиция из ошибочной строки отсутствует в снимке и будет скрыта у гостя. **Рекомендация: «всё или ничего»** и отклонение всего снимка при валюте, отличной от валюты заведения (строгая форма ADR-7.4); заранее проверить файл — `check` или `import --dry-run`.
2. **Где хранить хеш и время синхронизации** (arch, вопрос 1). **Решение ADR-8.5:** журнал `menu_sync_runs` в #8 (ревизия `0005`); хеш последнего применённого снимка — в журнале, `connectors.last_menu_hash`/`last_menu_sync_at` в #16 не нужны, вместо них `menu_sync_runs.connector_id`. Уточняет ADR-7.7, нужно подтверждение пользователя.
3. **Защита от массового скрытия** (arch, вопрос 8). **Рекомендация (ADR-8.4):** отказ `mass_hide`, если скрывается не меньше 10 позиций и не меньше 30 % видимых, снимается `--allow-mass-hide`; пустой снимок отвергается всегда. Для `PUT /menu` порог решается в #16.
4. **Колонка `is_available` отсутствует** (arch, вопрос 4). **Рекомендация:** колонка необязательная; нет колонки — наличие существующих позиций не меняется (ручной стоп-лист админки не затирается), новые получают `true`; выгрузка «restoran» колонку заполняет.
5. **Смысл `menu.disabled` в кассе** (arch, вопрос 6): временный стоп-лист или снятие с продажи? **Рекомендация:** пока по ТЗ A.2 — наличие (`is_available = 0`); уточнить у заведения; если это «снято навсегда», позиции с `disabled = 1` не выгружать (они будут скрыты).
6. **Как получить живые данные «restoran»** (arch, вопрос 5). В дампе `restoran(3).sql` нет строк `menu`, а каталог MariaDB 10.3 не открывается запущенным MySQL 8.0. **Рекомендация:** переключить OpenServer на модуль MariaDB-10.3-x64 (предварительно скопировав `userdata/MariaDB-10.3-x64`) и выполнить `php yii ai-export-menu`; иначе — свежий дамп от заведения.
7. **Где код выгрузки** (arch, вопрос 7). **Рекомендация (ADR-8.8):** команда Yii2 `php yii ai-export-menu` в репозитории кассы (`MenuSnapshotBuilder` переиспользуется в #18); в ai-waiter — только формат, пример, инструкция и `local-data/` в `.gitignore`.
8. **Как указывать заведение в CLI** (arch, вопрос 3). **Рекомендация:** обязательный `--tenant UUID`; подставлять «единственное заведение в БД» не нужно — неявно.
9. **Импорт по расписанию** (ТЗ 4.2). **Рекомендация:** вне #8; Планировщик заданий Windows или cron запускают тот же CLI. Встроенная периодическая задача — отдельная story, если понадобится.
10. **Набор тарифов.** **Рекомендация (ADR-8.3):** тарифы — из колонок `price_<tier>`; тариф, исчезнувший у позиции, удаляется из `menu_item_prices`, и стол этого тарифа получает цену `default`.
11. **Десятичная запятая.** **Решение ADR-8.2:** допускается только в CSV с разделителем `;`; разделители тысяч — ошибка.
12. **Категория без позиций.** В формате «строка = позиция» её не передать. **Рекомендация:** категория, которой нет в снимке, скрывается; категория без видимых позиций остаётся видимой, а гостевое меню (#10) не показывает пустые категории.
